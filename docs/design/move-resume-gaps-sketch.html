Move: a moved session should resume on the new Mac

What a session needs after "Move to another Mac" that doesn't come along today, and four ways to close the gaps. Sample data throughout: profile Studio, account sam@example.com, project ~/code/garden-app, worktree wt-forms, session "Fix the sign-up form".

Evidence: a real export → import with cl_audit's own engine into a fresh throwaway home (the new-Mac stand-in), and the resume rules read from Claude Code 2.1.318's and the Claude app's program text. The resume itself wasn't run: that needs a signed-in Claude Code and launching the programs, which the operator's second-user test will show.

Options

A. Folders: find or pick each session's folder

Import side · fixes the refusal and the hidden list
Does
Import checks each session's folder. At the same path: nothing to do. Missing or moved: listed with "Pick its folder on this Mac". A picked folder moves the conversation to that folder's name and rewrites the paths in the conversation and the Code-tab entry. A worktree that isn't there is dropped from the entry, so the session runs in the project folder.
Plus
A0, the small first step: mark imported entries the way the window marks its own imports, so the Code tab offers "Choose folder" instead of refusing. Seen only in the program text: the second-user test confirms it.
Size
nothing new in the file
Secrets
none new
Cost
A0 small, A medium (rewriting the conversation's lines safely)
Move preset
always on it's part of Import

B-lite. Code: a checklist, not the code

Export records, Import shows · fixes "what do I need to fetch?"
Does
Per project: the git remote (with any user name or token stripped), branch, last commit, and how many commits weren't pushed and files weren't committed. The Export page warns first ("garden-app: 3 commits not pushed, push them before you move"). The Import page shows a checklist: clone github.com/…/garden-app at ~/code/garden-app, check out feature/forms.
Size
bytes
Secrets
low once the remote URL's credentials are stripped
Cost
small to medium (read-only git on the old Mac)
Move preset
on

B. Code carried

Export and Import · fixes the code itself
Does
Everything in B-lite, plus: on import, "Clone it here" for a missing repo at the same path (git with the person's own credentials, on their click). In the encrypted image only: a git bundle of the unpushed commits and a patch of the uncommitted changes, applied on request. A folder that isn't a git repo is listed, and included only on request, with a size cap.
Size
bundles KB–MB; folders up to the cap
Secrets
high: uncommitted files can be .env or keys (image only, scanned and listed)
Cost
large; cl_audit starts running git on the new Mac
Move preset
off opt-in per project

C. Side files of each moved session

Export and Import · fixes Rewind, tasks, plans, history, trust
Does
Carries, per moved session: its task list, its plan, its prompt-history lines with their pasted text, and its project's trust and allowed tools. All in the image only, with the paths re-pointed when A picks a new folder. Rewind's file history is a row of its own, with its size shown. The project's MCP servers follow E2b's MCP rules, left out until Add them. Not carried: session env (hooks write it again; it holds tokens), image cache, shell snapshots, debug files and old todos.
Size
small, except Rewind (MB–hundreds of MB)
Secrets
high for prompt history and pastes (image only, key scan listed)
Cost
medium
Move preset
on tasks, plan, history, trust · off Rewind (size)

Proposed order

  1. A0 + A + B-lite. A moved session opens in the right folder, and the person knows what code to fetch. That is the blocker itself.
  2. C. Rewind, tasks, plans and up-arrow history come along; trust isn't asked again.
  3. B, if wanted: unpushed and uncommitted work travels in the image; "Clone it here" on the new Mac.

For the operator to pick

  1. Which options, and in what order (proposed: A0 + A + B-lite, then C, then B if wanted).
  2. Rewind's file history in a move: on by default, or a row you turn on (it can be hundreds of MB)?
  3. B: should cl_audit ever run git on the new Mac ("Clone it here"), or stay a checklist?
  4. Project memory for a move: added by default on import (it belongs to the sessions), or left out as today?
