cl_audit architecture: today, and the proposed modules

Built from two read-only audits of cl_audit at 26.11.25 (59b3dbf), compared with cl_quick (fa661ea) and claude-transplant 4.2.1. Every box names the real type, file or path, and red numbers mark the problems the audits found. Nothing has been changed.

In one line: cl_audit is two processes, the background agent and the app, plus Dock-icon copies and a sandboxed widget. They share about 15 files on disk, with no shared code layer between them. Account and usage rules are decided again on every screen, about 45 times. The six data-moving flows each have their own writer, receipt format and window handling (14 writers, 6 receipt formats, 4 window state machines). The proposal is three libraries on two foundation layers, with thin flows on top and screens that only draw.

1 · Today: processes, files and who touches what

Arrows show reads and writes. Each red number is a finding, explained below the diagram.

Claude's own files and processes cl_audit agent process cl_audit app process cl_audit's state on disk surfaces (each decides again)
1
Two writers of the status file. The app rewrites it without the agent's clash check. The agent won't overwrite it until its own state changes, so a wrong answer can stick.
2
The widget has its own copy of the reader. It knew none of the account rules until 26.11.25 patched it separately, and a renamed field would blank it silently.
3
Quick chat merges Claude Code's live limit events into the profile's level. 26.11.25 fixed this for the split case only.
4
The flows don't see each other's unfinished work. A restore or import can run on top of a half-finished switch, and the reverse; their Undos then disagree. High.
5
A switch drops a scheduled task whose id the target account already has. The source's copy survives only in the receipt and the backup. claude-transplant refuses this case. Data loss.
6
The Claude app's pending-write file (local_*.json.tmp) is left behind on a switch, so the app may bring the session back on restart, in both accounts. claude-transplant moves it together with the session file. Unsure.
7
Uninstall and Removal ignore unfinished work. Uninstall deletes every receipt and parked original. Removal hard-deletes a folder even when the window didn't quit within 5 s.
8
14 hand-written "create a new file safely" writers. Only some flush to disk, only one refuses symlinks when cloning, and none records the file's identity. There are also 6 receipt formats and 4 different "is Claude running" checks.

2 · Target: three libraries on two foundations, flows on top, screens only draw

Each library is a static Swift module compiled before the app, with only Foundation and Darwin, never AppKit or SwiftUI. A higher layer may use a lower one, never the reverse. The cl_quick tags mark what that app would share.

Injected seams: the folders' root paths, a clock (now:), ProcessRunner, WindowControl, plus KeychainReader and UsageAPI in the agent only. Every check suite keeps its throwaway HOME.

3 · An account switch in the target, step by step

Combines claude-transplant's way of moving sessions with cl_audit's sign-in side. Each step names the part that does it.

1
app consent sheet
Ticked box, ConsentLog line. Cancel writes nothing.
2
flow FlowGate.begin(.switch)
flock on the shared lock path, the window mark, and a check for any unfinished receipt of any kind for this profile. If one exists: refuse, and offer Finish or Undo for it.
3
flow Backups.make
Full backup of entries, sidebar and transcripts into backups/<id>, renamed into place with RENAME_EXCL. Better than claude-transplant, which keeps only parked copies.
4
app WindowControl.close
Quit the Claude window, confirm by process identity (pid plus start time), with a stall watchdog. If it doesn't close: stop, nothing moved.
5
flow SessionTransfer.run
WindowList per scope. Move whole units (forks, notify, routines), and hold a unit rather than split it. Refuse a differing task twin. For each record: CreateOnly.write (fsync, dev/ino in the journal), check the source before and after, then park it together with its .json.tmp. Sequenced journal.
6
claude CLI sign in
claude auth login --email <target> in Terminal, on the folder. FolderGuard never makes a missing folder. No Keychain read by cl_audit.
7
flow SignInWatch.judge
Watches .claude.json every 2 s for up to 10 min. Matches by id, else email plus organisation; also links sign-ins made elsewhere. Shared with cl_quick.
8
app WindowControl.reopen
Always reopens a window it closed, on success, timeout or cancel (today's switch never does).
9
flow ReceiptStore
The receipt is closed when the Claude app reaches the account (at most 24 h). Otherwise: Undo, which reverses only unchanged steps, or Leave it as it is.

For your review

  1. The layering above: ProfileCore, ClaudeFiles and Transfer on top of SafeFiles, Processes and SecretScan, with the flow engines on top of those, and screens that only draw. OK, or change it?
  2. Fix the two data-loss bugs now, before the refactor. #4: one flow running on top of another's unfinished work. #5: a switch dropping a task. Each is a small fix that ships on its own. I recommend this, since the full refactor will take weeks.
  3. Point 6 (the Claude app's .json.tmp file left behind) is unconfirmed. A quick check on a test profile would settle it before we change anything.
  4. Sharing: cl_quick takes ProfileCore, the account reader in ClaudeFiles, and SignInWatch. It moves no sessions, so it doesn't need the rest.
