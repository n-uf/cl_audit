Profile settings ▸ Claude Code: changing a profile's account

What happened today, as cl_audit saw it:

  1. The Claude window for Main moved to ben@example.com first, and nothing in cl_audit said so.
  2. Claude Code in ~/.claude stayed on ann@example.com, so cl_audit kept showing ann@example.com's numbers.
  3. You signed in again in Terminal. cl_audit then showed a red "Wrong account" until Refresh now, because its agent still held the old sign-in.
  4. Main is still linked to ann@example.com behind the scenes.

Below: two ways to draw the card (A and B) and a guided page (C). The switcher steps both cards through the same six moments, so you can compare them. They build on the seat design from 25 October: one profile per account seat, and every sign-in state named. Its last two stages (showing the states, linking a profile to another account) aren't built yet; these sketches are their wording and layout.

In every option.
  • No Refresh now needed: cl_audit reads the sign-in again as soon as the Claude Code folder's .claude.json names another account, so the stale red state from today doesn't happen.
  • Sign-in stays in Claude's own screens. Terminal runs claude auth login --claudeai --email <new> with the new email filled in, so a browser signed in to the other claude.ai account doesn't slip through.
  • Linking compares account ids and is refused when another profile has that account. Name, look, Dock place and settings stay.
  • The Claude window is checked too, by the account id the Claude app saves. A window on another account is a warning; the numbers come from Claude Code.
Moment
Main is linked to ann@example.com. Claude Code and the Claude window are both signed in to it, which is how every profile should be most of the time.

Steps

  1. Sign Claude Code in to ben@example.com
    Terminal runs Claude Code's own sign-in for ~/.claude, with the email filled in. cl_audit sees .claude.json change and reads the new sign-in at once.
  2. Claude window
    It's already on ben@example.com (it moved first). Otherwise: quit it, open it, and sign in with Claude's own window, as New profile does.
  3. Code sessions in the window optional
    The window lists only the signed-in account's Code sessions, so Main's earlier ones stay under ann@example.com. For the standard window, claude-transplant can move them (how-to, with every other Claude window quit first). Nothing here moves them.
  4. Link Main to ben@example.com
    Keeps Main's name, look, Dock place and settings. Refused if another profile has the account by then.

Recommended: B for the card, C for the switch. The trouble today was silent: the window moved, Claude Code didn't, and no lamp lit. B makes both sign-ins and the link visible all the time, and C walks the switch so nothing is forgotten (the window, Claude Code, the link, what stays with the old account). Pick A instead if you'd rather keep the card as it is and add only a key.

Open points

  • Numbers hidden while the folder is on a new account? The seat design says yes: they'd be the new account's, shown under the old link. With the automatic re-read it lasts only until you link or sign back in.
  • Moving the window's Code sessions. C's step 3 only links to a how-to for claude-transplant (standard window only). Moving them inside cl_audit would be a later, separate feature.
  • The old account afterwards. The last step offers "Add ann@example.com as a profile…", so its limits stay watched. Keep that key, or leave it out?
  • Names. "Switch…" (A) and "Change account…" (B, C); "Link Main to ben@example.com". In the README's words, "account" is the claude.ai account and "profile" is cl_audit's setup.
