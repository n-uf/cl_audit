cl_audit: clean-up, uninstall, Claude updates

Answers to three questions, with what the code and your Mac's Claude logs show today and a recommendation for each. They fit the background-agent design being built now. Concept only: nothing changes until you pick.

In short.
  • Leftover apps: yes, automatic clean-up makes sense, and the agent is the right owner. It runs at login, after every change and a few times a day. It removes only things it can prove are cl_audit's, and never a Claude Code or Claude window folder.
  • Uninstall: there's none today. Dragging cl_audit to the Trash leaves every Dock icon app running, starting at login and reading usage. Add Uninstall cl_audit… with a per-profile choice of folders, a command-line version, and a self-clean-up when cl_audit is dragged to the Trash.
  • Claude updates: you're right, they aren't graceful with several windows. Your logs show an update that couldn't install for 17 hours while other Claude windows were open. Each attempt closed the window that tried, for about 5 minutes. The agent can fix it: when one window starts updating, it quits the others normally, lets the update install, then reopens every profile's window with its own folders.

What it sweeps:
  • unwanted apps;
  • duplicates of a wanted profile;
  • leftovers in all six Library places (also web storage and app support);
  • saved usage of unknown profiles;
  • stale pins and recent-app entries;
  • old temporary scripts.
With "Usage in the Dock off removes the app", the same sweep keeps /Applications to exactly the profiles that show in the Dock.

2Uninstall cl_audit

There's no uninstall today: nothing in the menus, Settings or the README. Dragging cl_audit.app to the Trash leaves all of this behind:

  • every Dock icon app in /Applications, still pinned, still starting at login and reading usage;
  • with the agent design, a background item pointing into the trashed app (what macOS does with it is to be checked);
  • the profiles file, saved usage, preferences and caches;
  • every profile's Claude Code folder and window data folder, which is fine: those are yours to keep or delete.

3Claude windows and Anthropic updates

Every Claude window, the standard one and each profile's own, is a separate run of the same /Applications/Claude.app (now 3.6556.2). Claude updates itself with the usual Mac updater: it downloads in the background, then installs when that window quits or restarts, and after some hours it restarts itself to install. All windows write one shared log, so the updates can be followed there.

What your logs show (22–23 Oct)

21:12 · 01:00 · 02:26The same again, "failed to apply" 1 and 2 times; each time the window is gone for a while

  • Not graceful: while other windows are open, the update most likely can't install. The window that tries disappears for minutes and comes back on the old version, again and again.
  • Profiles survive the restart: the restarted window came back with its own data folder, not as the standard window. That's one observation; the agent should still check for it.
  • Windows that keep running stay on the old version until they restart. Claude Code sessions inside a window stop when it quits for an update ("Stopping 5 active sessions on quit").
  • cl_audit today: a Dock icon that follows its window waits 10 s, then quits during the 5-minute gap, and nothing reopens the window. With the agent, usage keeps being read, but the window still stays closed.

Recommendation: the agent helps Claude update

Notice

How
A Claude window quits and Claude's installer process appears, or the app on disk changes version. The agent records which profiles had a window open, and on which version.

Clear the way

Ask (default)
The main display says Claude update waiting · 2 windows hold it with Restart Claude windows. The card of each window that's running Claude Code sessions says so.
Or automatic
A General setting: "Claude updates: Ask · Restart windows when idle".
Then
Each remaining window gets a normal quit, so Claude asks about unsent work, shown as "Claude is asking · Show", as today.

Reopen

How
Once the update has installed (the version on disk changed), every profile whose window was open gets it back with its own data folder and Claude Code folder. The display says Claude updated · 3.6556.2 · 3 windows reopened.
Guard
If Claude comes back as the standard window for a profile that has its own, the agent quits it and opens the right one.

Stay calm meanwhile

Rules
While an update restart is under way, no Dock icon follows its window and no window follows its Dock icon. Cards say "Updating Claude…".
Any time
"Restart all Claude windows" in the cl_audit menu and the launcher does the same quit-all and reopen-each by hand.
Limits. cl_audit can't see "update downloaded" before a window quits without reading Claude's private files, so the first signal is that quit. Whether other open windows are what blocks the install is the most likely reading of the logs, not proven; the first build should confirm it.
