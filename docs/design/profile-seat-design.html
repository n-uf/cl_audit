cl_audit · profiles and Claude account seats

A profile is always linked to one Claude account seat. cl_audit stores that link itself and checks every sign-in against it, so a change of account is never silent. Draft for review, 2026-10-25; nothing here is built yet.

Decided

  • One profile per seat, strictly. A second profile for a seat that already has one is refused.
  • Every set-up profile has exactly one seat. Only a profile still being set up has none yet.
  • Re-linking a profile to another seat keeps its name, look and place in the Dock.
  • The Claude window signed in to another account is a warning, not an error: the usage numbers come from Claude Code and stay right.
  • The Dock icon app's file stays named after the profile (cl_audit Work.app).

What cl_audit keeps

In each profile (profiles file)

  • The linked seat: account id, organisation id, plan, email (shown only), linked at.
  • Everything it keeps today: name, label, folders, look, Dock and opening settings.

In each Dock icon's status

  • Signed in now, in the folder: account id, organisation id.
  • Signed in now, in the Claude window: account id.
  • The state from the table above.

Rules

  • Checks compare ids; the email is only shown, so hiding emails weakens nothing.
  • One profile per seat, enforced in Settings and New profile.
  • Ids aren't secret (no tokens); tokens stay in the Keychain as today.
